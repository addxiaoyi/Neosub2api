# 前端 UX 走查报告（unified-2api）

- 走查时间：2026-11-02
- 范围：登录、仪表盘、账号、服务商、密钥、设置（6 个页面）
- 方式：基于当前工作区源码独立执行 `npm run build:export`，静态产物由 8041 静态服务（`/api` 反代到 8031）托管；控制面 8031 使用临时数据目录，未触碰 8010 开发实例。浏览器为 Edge（Playwright 驱动），空数据 + 模拟慢网/断网两种状态。
- 只读约束：走查阶段未修改 `apps/web/`、`apps/control/` 内任何源码；截图见 `docs/ux-shots/`。
- 修复复核（2026-11-02）：已按本报告修复 U1–U5、U7、U9，逐条状态与证据见文末「修复状态」；复核截图在 `docs/ux-shots/after/`。

## 结论

**整体可用度：可用，但“可发现性”和“错误态表达”拖后腿。** 登录、导航、基础增删改都能跑通，页面风格统一，空态大多有明确文案；但服务商表格在标准桌面宽度下就裁掉了右侧核心操作，加载失败被显示成“没有数据”，错误提示直接透传英文技术信息。这些不影响系统功能，却直接影响用户判断和操作。

最影响使用的三个问题：

1. **服务商表格在 1440 宽度就显示不全**：`上游地址`、`启用` 两列完全在可视区外，用户看不到启用开关，也不知道可以横向滚动；768 下只剩前 1～2 列。设置页的「服务商接入」是同一个组件，问题相同。
2. **加载/失败态的语义是错的**：仪表盘加载中直接显示 `0`、`全部正常`；服务商加载失败时显示“没有登记任何服务商”，唯一提示是英文 `Network Error`，既没有重试入口，也分不清“没有数据”还是“请求失败”。
3. **添加账号整条链路走不通（blocker）**：账号页主 CTA「添加账号」请求 `POST /api/auth/start`，控制面没有该路由（网关日志实测 405），二维码区域永远空白，用户只看到红色 `Method Not Allowed`，既无法判断原因，也没有可执行的下一步。

## 重点核对项结论

## 走查限制

- 临时环境无真实账号，账号页仅覆盖空态与添加弹窗错误态；“账号删除确认”只从代码路径确认走 `ConfirmDialog`，未做运行时验证。
- 添加账号的 `Method Not Allowed` 已核对网关日志：`POST /api/auth/start → 405`，控制面路由表无该端点，与上游是否启动无关；这是链路缺失，不是本轮隔离环境造成的假象（复核时已补齐该路由）。
- 深色主题已补测风险说明与 danger 徽章：light 5.84:1 / dark 11.97:1，徽章 light 4.77:1 / dark 5.52:1。
