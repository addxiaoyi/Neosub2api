# 前端多语言（i18n）

`apps/web` 的界面文案全部落在 `lib/i18n/`，五种语言：`zh-CN`、`zh-TW`、`en`、`ja`、`ko`。
本文件说明键的组织方式、基准语言、可回退项，以及新增语言和校验脚本的用法。

## 1. 文件分工

| 文件 | 职责 |
| --- | --- |
| `apps/web/lib/i18n/locales/*.json` | 五种语言的字典，只放文案，不放代码 |
| `apps/web/lib/i18n/config.ts` | `LOCALES` 清单、`DEFAULT_LOCALE`、浏览器语言识别 |
| `apps/web/lib/i18n/index.ts` | 点分键查找、复数选择、`{name}` 插值、`t()` / `tp()`、回退链 |
| `apps/web/lib/i18n/provider.tsx` | React 上下文：`I18nProvider`、`useT()`、切换语言并写入 localStorage |
| `scripts/check_i18n.py` | 键集与源码引用的守卫脚本，CI 执行 |
| `.github/workflows/ci.yml` | `frontend` job 里的 `i18n 键集校验` 步骤 |

## 2. 键的组织方式

### 2.1 界面键：点分命名空间 + 字符串叶子

按页面或功能分组，层级与 `t("a.b.c")` 的路径一一对应：

```json
{
  "common": { "save": "保存", "cancel": "取消" },
  "accounts": { "title": "账号", "deleteDesc": "删除后不可恢复。" }
}
```

- 叶子必须是字符串，支持 `{name}` / `{count}` 占位（`index.ts` 的 `interpolate`）。
- 键名用英文，值用各语言译文；键名与文案不建立额外映射。

### 2.2 复数键：只有 `en` 用 `.one` / `.other`

```json
"format": {
  "minutes": { "one": "{n} minute", "other": "{n} minutes" }
}
```

非英语语言同一语义只用基础字符串键：

```json
"format": { "minutes": "{n} 分钟" }
```

取值时 `translate` 取到对象就交给 `pluralOf`，按 `Intl.PluralRules` 选分类，缺分类时退回 `other`
（`lib/i18n/index.ts:75-84`、`lib/i18n/index.ts:102-107`）。调用方统一写
`t("format.minutes", {count, n})`，见 `lib/format.ts:15`。

### 2.3 短语表：`phrases`

`phrases` 是「中文源文 → 译文」的平铺表，键不是英文键名，而是中文源文：

```json
"phrases": { "API 密钥": "API key" }
```

用于设置页这类与上游 `config.json` 一一对应的数据表文案，省掉「键名 ↔ 文案」的映射维护
（`index.ts:17-25`）。取用入口是 `tp(source)` / `translatePhrase`，而不是 `t()`。

## 3. 基准语言的选择

- `zh-CN` 是源语言：`DEFAULT_LOCALE = 'zh-CN'`（`config.ts:13-14`），运行时缺键回退到它，
  所以它必须拥有全部界面键（`phrases` 除外，见下）。
- `en` 是复数形式的定义语言：只有它写 `.one` / `.other`，其余语言用基础字符串。
- 校验脚本以两者的并集为基准：任一基准缺失的键，在其他语言里出现即视为「真缺」，同时在基准语言自身也会被报出来。

## 4. 设计性回退（不算真缺）

| 情形 | 依据 | 脚本处理 |
| --- | --- | --- |
| `phrases.*` 在 `zh-CN` 中不存在 | `translatePhrase` 取不到时原样返回中文源文（`index.ts:124-128`）；`phrases` 本就是后端运行时报文表，源语言无需翻译 | 界面键比较时整体排除 `phrases`；短语表只拿 `en` 与其余三种语言对齐。短语缺条只算软缺，不触发 `--strict` |
| 非英语语言用基础字符串代替 `.one/.other` | `pluralOf` 只在取到对象时才按复数分类；字符串直接使用（`index.ts:27-35`、`75-84`） | 复数组归一成基础键再比较，不把 `.one/.other` 报成缺失 |
| 目标语言缺界面键时页面仍可用 | `translate` 依次回退「当前语言 → `zh-CN` → 键名」（`index.ts:102-107`） | 仍计为真缺：回退只是兜底，不代表翻译完整 |

## 5. 新增一门语言

1. 在 `apps/web/lib/i18n/locales/` 下新增 `<locale>.json`，以 `en.json` 为模板补齐：
   - 全部界面键（`phrases` 以外的所有叶子）；
   - `phrases` 表需覆盖 `en.json` 里的全部中文源文键（缺条会回退中文，脚本记为软缺）。
2. 在 `config.ts` 同步四处：`LOCALES`、`LOCALE_LABELS`、`matchLocale` 的语言前缀分支；
   若该语言是新的源语言，才需要改 `DEFAULT_LOCALE`（一般不动）。
3. 跑 `python scripts/check_i18n.py --strict`，确认真缺为 0。
4. 提交后 CI 的 `frontend` job 会自动执行同一命令。

## 6. 脚本用法

```bash
python scripts/check_i18n.py           # 人类可读表格
python scripts/check_i18n.py --json    # 机器可读 JSON（CI/工具消费）
python scripts/check_i18n.py --strict  # 有真缺时以非 0 退出
```

输出列含义：

| 列 | 含义 |
| --- | --- |
| 叶子 | JSON 里的字符串叶子总数，含 `phrases` 与 `.one/.other` 拆分 |
| 界面键 | 去掉 `phrases`、复数组归一后的界面键数 |
| 短语 | `phrases` 表的条目数 |
| 复数组 | 该语言用 `.one/.other` 对象的键数（只有 `en` 非 0） |
| 真缺 | 基准语言有、该语言没有的界面键 |
| 多余 | 该语言有、基准语言没有的界面键 |
| 源码缺 | 源码字面量引用、但该语言字典里没有的键 |

退出码：

- `0`：没有真缺；`--strict` 下也通过。
- `1`：`--strict` 且存在真缺（含基准语言自身漂移、源码字面量引用缺键）。
- `2`：脚本无法运行（语言文件缺失、JSON 非法、`config.ts` 解析失败）。

`--strict` 只拦「真缺」和「源码字面量引用缺键」。以下只告警、不拦：

- 多余键、源码零引用键（动态拼键可能让扫描器看不到引用）；
- 短语软缺（回退中文源文是设计行为）；
- 动态模板在字典里零匹配。

## 7. CI 接线

`.github/workflows/ci.yml` 的 `frontend` job 中，checkout 之后依次是：

1. `Set up Python`（`actions/setup-python@v5`，Python 3.12）；
2. `i18n 键集校验` → `python scripts/check_i18n.py --strict`；
3. 之后才是 Node 依赖安装、lint、typecheck、build。

校验不依赖 npm，放在最前面以便失败时快速中断。该步骤失败即 job 红。

## 8. 误报是如何收敛的

脚本是源码扫描器而不是 TypeScript 编译器，为避免「假红」挡合并，做了这些收敛：

- 只把首段是已知顶层命名空间的点分字符串当候选键，避免把文件名、URL、CSS 类当成键；
- 跳过对象属性名（`{'a.b': ...}`）与下标访问（`obj['a.b']`）；
- 先用状态机去掉 `//` 与 `/* */` 注释，注释里出现的键不作为引用
  （例如 `lib/utils.ts` 注释中的 `format.copyText` 不会被误判）；
- 动态键模板转成正则匹配：`accounts.managed_${...}`、
  `settings.runtime.${...}.label/.desc`，命中的字典键计入「已引用」；
- `phrases` 不参与界面键比较，短语缺条只告警；
- 复数组归一，不把设计性回退报成缺失。

如果仍出现误报：用 `--json` 查看具体键，优先修正扫描规则（例如新增动态模板模式），
**不要**为了让 CI 变绿而放宽「真缺」的判定。
