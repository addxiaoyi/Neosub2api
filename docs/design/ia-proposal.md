## 0. 结论

1. **底部五项 dock 不适合桌面端**。它有 5 个入口，而实际存在 11 个页面；`logs / models / playground / security / stats / tasks` 六个页面已经实现、在 i18n 里有文案，但没有任何导航入口。
2. **桌面改左侧分组导航（4 组 11 项 + 1 个新增入口）**，移动端保留 dock 但收敛为「4 个主入口 + 更多」。
3. **术语只留一套**：`服务商`（provider 注册项）、`上游服务`（服务商背后的远端服务，仅用于状态/诊断）、`独立进程`（sidecar）。`渠道` 全面废弃，`provider` 只留在代码和 API 字段里。
4. **风险必须三重编码**（图标形状 + 文字 + 边框/底色），不能只靠红/琥珀。`safe` 也要显示「可商用」，否则「没有徽章」和「数据缺失」无法区分。
5. **品牌建议「渡口 / Ferry」**：网关的本质是把请求摆渡到不同服务商，名字有实义、不依赖「云/枢/智」这类填充词。

## 2. 导航结构

### 2.1 桌面端：底部 dock 不合适

判断依据（全部可对应到代码）：

1. **容量和发现性不够**：5 个图标承载 11 个页面，6 个页面只能靠记 URL 进入；dock 只有图标 + hover 标题，没有分组，也没有「当前在哪一页」的标记——[FloatingDock](file:///d:/qwq/项目/unified-2api/apps/web/components/ui/floating-dock.tsx#L21-L50) 根本没有 `active` 参数。
2. **位置可变**：dock 支持拖拽并写入 `localStorage`（L350-L389、L118-L131），同一产品在不同人的屏幕上导航位置不同，截图/录屏/远程协助都对不上。
3. **与内容抢空间**：页面底部预留 `pb-24` 给 dock（[layout.tsx L45](file:///d:/qwq/项目/unified-2api/apps/web/app/(main)/layout.tsx#L45)）；首次进入还有一块 17rem 宽的引导浮层压在表格与开关上（U10）。
4. **版本切换没有归属**：`RealmToggle`、`LanguageToggle` 被放在每页右上角（[layout.tsx L50-L53](file:///d:/qwq/项目/unified-2api/apps/web/app/(main)/layout.tsx#L50-L53)），但版本是全局筛选条件（账号/模型/测试台/任务都跟随），应该和导航在同一层。
5. **桌面端用移动导航的代价**：dock 原本是 codebuddy2api 的移动交互，桌面窗口越宽，导航越远离内容主区，右手操作路径也最长。

结论：**桌面改左侧栏；移动端保留 dock，但把 5 项改成 4 个主入口 + 「更多」抽屉**（更多里放日志、用量、模型、测试台、任务、安全、设置）。

### 2.2 目标结构

桌面左侧栏宽 208–224px，分 4 组，共 11 个现有入口 + 1 个新增（模型路由，见 §4）：

| 分组 | 菜单项 | 路由 | 分组理由 |
| --- | --- | --- | --- |
| 总览 | 仪表盘 | `/dashboard` | 回答「现在怎么样」，只读、无对象操作 |
| 总览 | 用量 | `/stats` | 与仪表盘同一问题域（趋势/消耗），只是粒度更细 |
| 资源 | 账号 | `/accounts` | 供给侧对象：登录态与积分 |
| 资源 | 服务商 | `/providers` | 供给侧对象：适配器注册表 |
| 资源 | 模型 | `/models` | 供给侧对象：可用模型目录 |
| 资源 | 模型路由 | `/models/routing`（新增） | 供给侧对象：模型名 → 服务商/实际模型的规则 |
| 资源 | 任务 | `/tasks` | 供给侧动作的结果：签到、自动任务、注册任务 |
| 接入 | 密钥 | `/keys` | 需求侧对象：谁可以调用 |
| 接入 | 请求日志 | `/logs` | 需求侧事实：每次调用发生了什么 |
| 接入 | 测试台 | `/playground` | 需求侧验证：用管理员权限直接试模型 |
| 系统 | 安全 | `/security` | 入站边界与审计 |
| 系统 | 设置 | `/settings` | 控制面自身配置（不含服务商） |

分组逻辑不是按技术层（前端/后端/网关），而是按**对象归属**：

- **总览**只读、按时间聚合；
- **资源**是「我们拿什么去提供服务」——账号、服务商、模型、路由、任务；
- **接入**是「别人怎么用、用得怎么样」——密钥、日志、测试台；
- **系统**是「控制面自己的边界」——安全策略与全局配置。

「请求日志」放接入而不是总览：它按单次调用可检索，是排障对象；总览里的图表是聚合事实，两者查询方式不同，合并会变成一张什么都装的大表。

### 2.3 导航行为规范

| 行为 | 规格 |
| --- | --- |
| 当前页 | 左侧 2px 强调色竖线 + 文字变强调色 + `aria-current="page"`；不只用底色 |
| 分组标题 | 小号大写/字重 500，非链接，不可聚焦 |
| 折叠 | 窗口 < 1180px 自动收成图标栏（仅图标 + tooltip）；提供手动折叠按钮，状态存 `localStorage` |
| 键盘 | Tab 顺序 = 分组顺序；`Enter/Space` 进入；不做自定义方向键，避免和浏览器习惯冲突 |
| 版本/语言 | 移到侧栏底部（版本在上、语言在下），与全局筛选的真实作用域一致 |
| 移动端 | 底部 dock：仪表盘、账号、服务商、密钥 + 「更多」；「更多」用现有 `Sheet` 组件 |
| 首次引导 | 改为侧栏顶部一次性提示条，不覆盖内容；不再跟随 dock 位置 |

### 2.4 设置页瘦身

| 现有 tab | 处理 | 原因 |
| --- | --- | --- |
| 服务商接入 | **删除** | 与 `/providers` 同一组件，同一对象两个入口 |
| 上游配置 | 保留，改名「运行配置」，描述注明「仅对 CodeBuddy 服务商生效」 | 内容是上游 `config.json` 的 10 个分组（排程/提示词/冷却/并发等），属于服务商运行参数，不是全局设置 |

## 5. 风险表达规范

### 5.1 先把三个维度拆开

现在一张表把「接入状态」和「许可证风险」都塞进状态列附近，用户无法判断红徽章是「不能商用」还是「没接好」。拆成三列/三块，互不替代：

| 维度 | 取值 | 展示位置 |
| --- | --- | --- |
| 许可证风险 | 禁止商用 / 需隔离 / 可商用 | 列表独立列 + 详情合规章 |
| 接入状态 | 已接入 / 占位适配器 / 独立进程 | 状态列 |
| 运行健康 | 正常 / 不可达 / 未知 | 仅详情（或仪表盘），列表不展示 |

数据事实：当前 12 个适配器中 `danger` 2 个、`warn` 0 个、其余 `safe`。**不要为了展示琥珀徽章伪造 warn 数据**；`warn` 在出现 GPL/LGPL 适配器时自然出现。

### 5.2 三档定义与文案

| 档位 | 判定（来自注册表） | 列表 | 详情 | 表单 |
| --- | --- | --- | --- | --- |
| danger 禁止商用 | 无 LICENSE、All Rights Reserved、PolyForm NC 等 | 八角形停止图标 + 「禁止商用」，深红文字 + 1px 同色描边，无底色 | 合规区块：「许可证：PolyForm NC 1.0.0」+ 完整中文说明 + 「该服务商不得对外提供服务」 | 启用/保存前必须勾选「我确认仅用于内部评估」，未勾选时主按钮 disabled |
| warn 需隔离 | GPL/LGPL 等传染性许可证 | 三角形警示图标 + 「需隔离」，赭黄文字 + 1px 虚线描边 | 合规区块：「仅以独立进程调用，主仓不链接其代码」+ 许可证名 + 运行时说明 | 表单顶部一条 inline 提示；保存放行，但首次启用弹确认（列出许可证与隔离方式） |
| safe 可商用 | MIT/Apache/BSD/本仓自研 | 对勾图标 + 「可商用」，中性灰文字，无描边无底色 | 合规区块只显示许可证名与「可自由合入、可商用」 | 无额外阻断 |

`safe` 必须显式显示「可商用」：现在 `risk_level !== 'danger' && !== 'warn'` 时什么也不渲染，用户看到的是空白，无法区分「合规」与「后端没返回风险字段」。

### 5.3 不能只靠颜色

| 手段 | danger | warn | safe |
| --- | --- | --- | --- |
| 图标形状 | 八角形（停止） | 三角形（警示） | 圆形对勾 |
| 文字 | 必带「禁止商用」 | 必带「需隔离」 | 必带「可商用」 |
| 边框 | 1px 实线 | 1px 虚线 | 无 |
| 行内位置 | 风险列固定在第 2 列，不随排序移动 | 同左 | 同左 |
| 颜色（仅辅助） | `#8c2f2f` on `#f8efee` | `#6f4a12` on `#f8f2e6` | `#4a5560` on 透明 |
| 对比度 | ≥ 7:1 | ≥ 7:1 | ≥ 4.5:1 |

字号从 10px 提到 12px，风险说明不再用 `text-destructive/80`（U7 实测 3.84:1）。不要用 emoji `⚠️`：屏幕阅读器会读出「警告符号」，且不同系统字形不一致，改为内联 SVG + `aria-hidden="true"`，语义由文字承担。

### 5.4 状态表达（空 / 失败 / 加载）

三态必须共享同一个容器尺寸，文案与操作不同：

| 状态 | 标题 | 说明 | 主操作 | 次操作 |
| --- | --- | --- | --- | --- |
| 加载 | 正在加载服务商 | 骨架行 3 条，不显示「0」或「全部正常」 | — | — |
| 空 | 尚未登记服务商 | 「控制面没有返回任何服务商。可能是首次部署，或注册表被清空。」 | 登记服务商 | 重新加载 |
| 失败 | 服务商列表加载失败 | 「无法读取注册表（HTTP 502）。这不代表没有数据。」 | 重试 | 展开诊断详情（折叠 URL/原始错误） |

失败态用 `role="alert"`，空态用 `role="status"`。顶部计数在失败时显示 `—`，在真空时显示 `0`——这是区分两者最省事的信号。

### 5.5 操作确认口径

| 操作 | 确认方式 | 理由 |
| --- | --- | --- |
| 删除密钥 / 删除账号 / 清空日志 | 二次确认弹窗（保留现状） | 不可撤销 |
| 停用服务商 | 二次确认；说明「停用后该服务商不再参与 /v1 路由」 | 影响线上流量，可撤销但用户不一定知道 |
| 关闭网关鉴权（允许匿名） | 二次确认 + 输入确认词或勾选风险告知 | 安全敏感，误触即暴露 |
| 启用 danger 服务商 | 勾选「仅内部评估」后确认 | 合规要求 |
| 启用 warn 服务商 | 首次确认（展示隔离方式），之后即时生效 | 降低重复摩擦 |
| 普通启停 / 备注 / 重命名 | 即时生效 + toast，提供「撤销」 | 低风险，避免过度打扰 |

## 6. 品牌命名

命名标准：能说明「多服务商收敛到一个入口」、2–3 个音节、中文可读、不依赖「云/枢/智/联」这类无实义词、能直接放进 `%s - 品牌名` 的标题模板。

| 候选 | 中文 | 一句话理由 | 风险 |
| --- | --- | --- | --- |
| **Ferry** | **渡口** | 网关就是摆渡：请求从下游进来，被送到不同服务商；中文名有画面，念得出来，不带行业填充词。 | 常见英文词，需查商标与域名；建议主用中文「渡口」，英文作副标。 |
| Manifold | 歧管 | 工程上「多路进气汇到一条出口」，正好是多 provider → 一个 `/v1` 的结构隐喻。 | 偏工程圈层，中文「歧管」不够顺口，适合做英文产品名。 |
| Switchyard | 编组场 | 铁路/电力里把多路车皮或电流编组、分流、停用的场地，贴合「控制面 + 网关」双职责。 | 词长，中文名有画面但不利记忆，适合做二级品牌或版本代号。 |

**推荐：渡口 / Ferry。** 现有 `WorkBuddy Manager` 的问题不是不好听，而是它只描述了 CodeBuddy 那一家上游，和「多服务商控制面」的事实相反。
